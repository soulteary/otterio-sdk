# OtterIO SDK v7.3.5

## Conditional uploads

[PR #13](https://github.com/soulteary/otterio-sdk/pull/13) fixes destination conditions in HTTP multipart uploads:

- Automatic `PutObject` multipart uploads retain `If-Match` and `If-None-Match` on `CompleteMultipartUpload`, where the destination object is committed. This covers seekable, streaming, parallel-streaming, and unknown-length uploads.
- Multipart initiation omits those destination conditions while preserving the options needed for completion. An upload session does not reserve the destination or establish that a later write will satisfy its condition.
- Conditional RDMA uploads return `InvalidArgument` before native transfer, reading the input, or falling back to HTTP. The native RDMA upload API cannot carry these conditions; both buffer and streaming RDMA uploads reject them explicitly.

`PutObjectOptions.SetMatchETag` and `SetMatchETagExcept` remain the existing public APIs. Single PUT and multipart completion send the requested condition to the server. The server must support and atomically enforce that condition at commit time: this SDK release does not add server capabilities or broaden the server's supported condition forms and deployment modes. For OtterIO, follow its [conditional object write contract](https://github.com/soulteary/otterio/blob/180cd6612bece209a898b69890010a6f72e97029/docs/otterio-limits.md#conditional-object-writes).

HTTP regression tests cover signature binding, preservation of initialization metadata, and rejected completion responses, including an XML error after HTTP 200. A failed precondition remains an error and is not retried as an unconditional write. Failed automatic multipart uploads still attempt to abort the upload session.

## Runtime and dependencies

- Keep the Go 1.27.4 minimum and the module path `github.com/soulteary/otterio-sdk/v7`.
- Identify the client User-Agent as v7.3.5.
- Include [PR #12](https://github.com/soulteary/otterio-sdk/pull/12): refresh the Go tool dependency graph, update the S3 example's progress-bar dependency to `github.com/cheggaaa/pb v1.0.30`, and pin the vulnerability scanner to `govulncheck v1.10.0`.

The original license, notice, and source copyright attribution are retained. This patch release does not change the public module path or introduce a new major-version API.

## Validation

Local validation with Go 1.27.4 on Linux amd64 passed the uncached short race suite, SDK builds, the pinned linter, and all example builds. The short race suite includes the HTTP conditional-upload regressions and the RDMA rejection tests; it skips the cases requiring a live S3 server.

These local checks did not include live-server or native RDMA validation. Mock HTTP coverage alone does not establish a server's conditional-write guarantees.

## Install and example versions

```sh
go get github.com/soulteary/otterio-sdk/v7@v7.3.5
```

The example modules retain their published v7.3.4 requirements. Their existing local checkout replacements make `make examples` compile against the local SDK source. If their version pins are updated, publish v7.3.5 first, then update the example requirements and verify their builds. Downstream consumers should likewise use the published tag; no unpublished version or additional replacement is needed.
